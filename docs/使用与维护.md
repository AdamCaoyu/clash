# 使用与维护

## 现有 OpenClash 入口

本次核对了现有订阅编辑页面：在线订阅转换启用、自定义模板为本仓库 `Clash-Full.ini`、UDP 启用、跳过证书验证停用、“使用规则集”停用。保留你的订阅和转换服务，不安装或替换服务。

### 更新步骤

1. 在“配置管理”备份当前配置和运行配置。
2. 在“配置订阅”保持现有订阅地址、转换服务和自定义模板地址不变，执行更新。该操作可能重载 OpenClash，安排在方便短暂断网时进行。
3. 打开面板，首次将 `台湾-固定` 选择为你常用的台湾节点，将 `新加坡-固定` 选择为可用的新加坡节点。模板不预知哪一个节点最稳定；首次默认取订阅顺序中的第一个符合条件的节点。
4. `🔐 稳定账号` 与 `🧭 日常代理` 默认引用同一个 `台湾-固定`。日常如需临时换线路，改“日常代理”的组选择，避免改共享的台湾节点而带动所有账号。需给单个国家另一个固定节点时可用“全部-手动”，不要用自动测速组承载敏感登录。
5. 检查 ChatGPT / Siri、Google 登录、GitHub、Microsoft、Netflix、iCloud 和国内网站。确认规则与出口后再长期使用。

固定策略不会自动按测速切换节点；节点失效时手动换。同组不同业务共用出口可以减少无意的 IP 切换，但机场可能更换出口 IP，固定节点不等于独享 IP，也不保证避免风控。订阅删除或重命名节点时，旧选择可能失效，更新后需重新核对。模板不给境外代理组自动补 DIRECT，无合格节点则 REJECT。

## 规则更新：使用已有功能

- 当前“使用规则集”关闭时，转换器将上游规则展开进 YAML。上游更新不会自行进入现有 YAML，需要更新订阅；现场看到订阅“自动更新”尚未开启。
- 如需规则自动刷新，可在同一订阅编辑页面将“使用规则集”设为启用，然后保存并更新配置。OpenClash 会传入 `expand=false&classic=true`，无需更换转换服务。
- 新模板使用原生 `clash-classic:` / `clash-domain:` 来源，间隔 86400 秒。兼容后端生成的 rule-providers 直接取规则源，不需要在运行期间依赖额外转换接口。实际刷新取决于路由器网络可达性和上游发布时间，是定时刷新，不是实时推送。
- 启用后检查配置是否包含 rule-providers、各规则集加载成功和 86400 秒周期。若现有后端不支持或报错，关闭此选项，保持静态展开模式。两种模式使用同一份模板。
- 规则源刷新与节点订阅更新是两回事；机场节点更新仍由已有订阅功能管理。不要同时叠加另一套第三方整套规则或“规则附加”覆盖同一业务，避免顺序冲突。

## 分类取舍

- ChatGPT 自有域名与 Apple Relay 共用 Apple Intelligence 组，默认同一台湾固定出口。
- MetaCubeX 的海外 AI 分类覆盖 Claude、Gemini、Copilot、Grok 等，单独可改国家；Google / GitHub / Microsoft 在其后，避免抢先吃掉 AI 子域。
- YouTube 等细分媒体规则放在 Google 前，Netflix 放在一般媒体前。
- PayPal / Amazon 独立业务组，但默认与重要账号共用出口。国内支付和购物跟随国内规则，不把所有“支付”统统代理；其他海外商家默认也走同一台湾节点，需例外时加入个人列表。
- 中国规则在具体业务之后、普通国外规则之前。漏网默认台湾，提升未知境外站点可用性；国内站点若需直连可补充 CaoyuDirect.list，或手动更改漏网组。
- 未启用全局广告/隐私追踪拦截；避免影响验证码、登录、支付或应用功能。
- Netflix 新加坡仅是用户偏好。可选片源与中文音轨/字幕受地区、版权、标题和个人资料语言共同影响，不保证比台湾丰富。先在 Netflix 个人资料中设置中文偏好，再测试实际节目。

## 回滚

先恢复路由器备份的旧 YAML 并应用。GitHub 源规则回滚使用 `git revert <本次提交>` 后推送 main，保留历史，不强制覆盖远端。回滚后需再更新订阅才会进入静态运行配置。

## 维护约定

编辑 `config/openclash.ini` 和 `list/` 中的个人规则，执行 `python3 scripts/sync_templates.py` 同步兼容入口与原生规则集，再运行测试。不要分别维护两份不同内容的 Apple 规则；`.list` 为源，`rules/clash/Apple.yaml` 为生成格式。

普通回归测试不需要网络。真实转换产物可用 `python3 scripts/validate_generated.py 文件.yaml` 检查静态规则；原生规则集模式还需提供下载的测试规则集目录。生成结果还应使用当前 Mihomo 的 `-t` 检查，不能用“YAML 能解析”代替内核验证。

本次没有改动路由器运行配置、全局 DNS 或账户设置；生效操作按上面的步骤进行。
